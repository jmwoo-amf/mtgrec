# 회의 로컬 녹음과 전사

`mtgrec` CLI 가 캡처와 전사를 하고 이 스킬이 그것을 부르고 결과를 요약한다.
**회의 중에 살아 있는 것은 도구이지 이 스킬이 아니다.** 스킬은 시작 명령을 내리고, 끝나고 나서
결과물을 다룬다. 그 사이는 `mtgrec` 이 띄운 로컬호스트 페이지가 맡는다. 실시간 전사가 흐르고,
발화가 쌓이면 논의 묶음 노트가 갱신되고, 트랙이 무음이면 그 자리에서 경고가 뜬다.

## 인자 해석

| 입력 | 모드 |
|------|------|
| `/rec start [제목]` · "녹음 시작" | **묻지 않고 즉시** 캡처 시작. 기본 = 원격 회의 + 헤드폰 (옵션 없음) |
| `/rec setup` · "rec 설정" | 설정 마법사. `references/setup.md` 를 따른다 |
| `/rec stop` · "녹음 끝" | 종료 → 전사 → 요약 → **Notion 페이지 생성**까지 (`config.notion.enabled` 일 때) |
| `/rec` (인자 없음) | 상태. 녹음 중이면 경과와 페이지 주소, 아니면 최근 세션 |
| `/rec live` | 진행 중 세션의 실시간 페이지 주소를 다시 알려준다 |
| `/rec transcribe [세션]` | 재전사. 이어서 용어 보정까지 |
| `/rec correct [세션]` | 용어 보정만 다시. 용어집을 고친 뒤 이걸 쓴다 |
| `/rec summary [세션]` | 요약을 다시 만든다. 터미널에 내고, `session.json` 에 `notionPageId` 가 있으면 그 페이지를 갱신할지 묻는다. 없으면 터미널만 |
| `/rec clean [--days N]` | 전사 끝난 세션의 오디오 삭제 |

## 시작할 때

**설정 파일 `~/.config/mtgrec/config.json` 이 있는지 본다** (`MTGREC_CONFIG_DIR` 가 있으면 그 아래). 없으면 `/rec setup` 을 먼저 돌린다. 단, `/rec start` 는 회의 직전이므로 설정이 없어도 기본값으로 녹음부터 시작하고, 설정은 `stop` 전에 하라고 한 줄 안내한다. 이 문서에서 `config.X` 는 그 파일의 필드다.

`~/.claude/bin/mtgrec` 이 있는지 본다. 없으면 이 스킬의 `tools/build.sh` 를 돌려 설치하고, 빌드가 실패하면 그 출력을 그대로 보여주고 멈춘다. 추측해서 다른 경로를 뒤지지 않는다.

세션은 `{config.storage}/{YYYY-MM-DD-HHMM-제목}/` 에 쌓인다. 설정이 없으면 `~/Recordings/mtgrec` 다. 실제 위치와 읽고 있는 파일은 `mtgrec config` 로 확인한다.

## `/rec start`

```
~/.claude/bin/mtgrec start "주간 회의"
```

**묻지 않고 즉시 시작한다.** 회의 직전·중에 도는 명령이라 왕복이 곧 비용이다. 확인 질문(제목 · 자리 · 마이크 설정)을 내지 않는다.

- **자리는 기본 = 원격 회의 + 헤드폰으로 취급한다** (옵션 없음, mic + sys 2트랙). 모르겠어도 일단 이 기본으로 시작한다. 기본 설정은 어떤 자리에서든 소리를 잃지 않는다. 대면이면 sys 가 빌 뿐 mic 이 회의실을 담고, 스피커 자리면 누화가 생길 뿐이다. 그 판정은 `stop` 의 peak 확인과 전사에서 한다
- **세션 이름은 캘린더의 현재(또는 직전) 일정 제목에서 접두어를 떼고 쓴다.** 캘린더 커넥터가 없으면 「수시 논의」로 시작한다. 이것은 저장 위치 아래 디렉터리 이름이고, Notion 회의록 제목은 `/rec stop` 이 따로 만든다 (`references/summary.md` 의 「제목」 절). 떼는 접두어는 `config.title.calendarPrefixPattern` 정규식이 정한다. 없으면 맨 앞의 대괄호 묶음(`[팀A]` · `[A / B]`)을 뗀다 (`[팀A] 주간 회의` → `주간 회의`). 대괄호 묶음은 캘린더에서 분류하려고 붙인 것이고 회의 주제가 아니다. 걸리는 일정이 없으면 「수시 논의」로 시작하고, 전사 후 실제 주제로 기록 이름을 맞춘다. 제목 때문에 시작을 지연하지 않는다
- `--mute` · `--mic-only` · `--sys-only` 는 **사용자가 자리나 녹음 범위를 명시했을 때만** 아래 표대로 쓴다
- 녹음 중에 「내 마이크는 빼달라」 고 하면 `stop` 후 같은 제목으로 `start --sys-only` 를 다시 띄운다. 진행 중 세션의 트랙을 바꾸는 명령은 없다. 앞 세션의 `mic.wav` 를 지울지는 묻는다

이미 녹음 중이면 `mtgrec start` 가 거부한다. 그때는 진행 중 세션을 보여주고 계속할지 끝낼지 묻는다.

### 실시간 페이지

`start` 가 `http://127.0.0.1:8477/?t=…` 를 함께 찍는다. **그 주소를 사용자에게 그대로 전달한다.**
토큰이 붙어 있어야 열리고, 서버는 루프백에만 뜬다.

| 페이지에 있는 것 | |
|------|------|
| 왼쪽 | 실시간 전사. 나 / 상대 색이 갈리고 인식 중인 문장은 회색으로 따라 흐른다 |
| 오른쪽 | 논의 묶음 노트. 지금까지의 결론 → 안건 카드(배경 · 내용 · 결론) → 액션 플랜 |
| 배너 | **상대 트랙이 60초 무음이면 여기 뜬다.** 회의 중에 고칠 수 있는 유일한 순간이다 |
| 버튼 | 「지금 요약」 즉시 갱신, 「녹음 종료」 `mtgrec stop` 과 같은 경로 |

노트는 새로 확정된 전사가 1500자 쌓이거나 마지막 요약 후 5분이 지나면 갱신된다.
`MTGREC_SUMMARY_CHARS` · `MTGREC_SUMMARY_SECONDS` 로 바꾼다.

**요약만 헤드리스 `claude` 를 부른다.** 오디오는 여전히 단말 밖으로 안 나가지만 전사 텍스트는
나간다. 그것을 원하지 않는 회의는 `--no-live` 로 시작한다. 페이지도 요약도 뜨지 않고
전사는 종료 후 온디바이스 패스로만 한다.

녹음이 끝나도 페이지는 10분 더 열려 있다. 회의 직후에 노트를 마저 읽는 시간이다.

한 녹음에 회의 여러 개가 섞일 수 있다. **전사 후 캘린더 일정 경계와 내용으로 나눠 기록한다.** 단, 세션 이름을 믿지 말고 실제 내용을 먼저 확인한다. 실제로 세션명은 아침 정기 회의였는데 전체가 다른 주제였고, 그 회의는 녹음 시작 전에 끝나 있던 일이 있었다. 이름만 믿고 나누면 없는 회의를 지어낸다.

### 자리별 옵션 (사용자가 자리를 명시했을 때)

**시스템 오디오 탭은 이 맥에서 소리가 재생될 때만 잡힌다.** 회의 앱이 이 맥에 붙어 있지 않으면 「상대」 트랙이 빈다.

| 자리 | 옵션 | 결과 |
|------|------|------|
| 원격 회의, 헤드폰 | (없음) | 최선. 나/상대가 깨끗하게 갈림 |
| 원격 회의, 내 맥은 회의에 붙어 있으나 소리는 회의실 장비로 들음 | `--mute` | **권장.** 탭은 받고 내 스피커는 안 움 |
| 원격 회의, 스피커로 들음 | (없음) | 동작은 하나 마이크가 상대 목소리를 주워 담음 |
| 회의실 대면, 내 맥은 회의에 안 붙음 | `--mic-only` | 전사는 되지만 **화자 구분이 없음** |
| 전화 통화 | `--mic-only` | 상대 목소리는 스피커폰이어야 잡힘 |
| 내 목소리를 남기지 않음 (듣기만 하는 자리, 내 발언 제외 요청) | `--sys-only` | 마이크는 aggregate 클럭으로만 쓰고 파일에 쓰지 않음. 상대 트랙만 남음. `--mute` 와 함께 쓸 수 있음 |

`--mute` 는 탭으로는 오디오를 받으면서 이 맥의 스피커로는 내보내지 않는다. 회의실에서 옆 사람 장비로 소리를 듣는 자리에 맞는 설정이고, 스피커가 울지 않으므로 마이크 누화도 함께 사라진다. **회의 앱 자체의 「오디오 끄기」나 「통화 나가기」를 쓰면 안 된다.** 그건 오디오 스트림 자체를 끊어서 탭이 아무 것도 못 받는다. macOS 볼륨을 0으로 내리는 것도 탭에는 영향이 없지만, `--mute` 를 쓰면 손으로 볼륨을 건드릴 필요가 없다.

`--mic-only` 로 갈 때는 **화자 구분이 없다는 것을 사용자에게 미리 말한다.** 전사본의 모든 발언이 「나」 트랙 하나로 들어가므로 누가 말했는지는 내용으로만 추정된다. 요약의 실행 담당은 전부 추정 표시가 되고, 화자 기준으로 발언을 가를 수 없다.

### 시작한 뒤 알릴 것

**참석자에게 녹음 사실을 알리라고 안내한다.** 당사자 녹음이 위법은 아니지만 외부 참석자가 앉은 회의에서 말없이 녹음하면 신뢰 문제가 된다. 알릴지 말지는 사용자가 정한다. 스킬이 대신 판단하지 않는다.

## `/rec stop`

```
~/.claude/bin/mtgrec stop
~/.claude/bin/mtgrec transcribe
```

**무음 판정은 peak 가 아니라 `transcribe` 가 찍는 트랙별 덩어리 수로 한다.** `--mic-only` 가 아닌데 **`sys (상대): 0 덩어리`** 면 상대 소리가 안 잡힌 것이다. 회의 앱이 이 맥에 붙어 있지 않았거나, 다른 출력 장치로 나갔거나, 회의 앱에서 오디오를 꺼둔 것이다. 그대로 넘어가지 말고 사용자에게 알린다. 이 경우 마이크 트랙만 남으므로 화자 구분이 없다.

**`stop` 의 peak 로는 이것이 안 걸러진다.** 실제로 두 세션이 sys peak 가 0.152 로 **정확히 같았고** 둘 다 덩어리 0 이었다. 고정 노이즈 플로어가 0.01 을 넘기기 때문에 peak 기준은 무음을 놓친다. peak 는 참고로만 보고, 판정은 `transcribe` 출력으로 한다.

`--sys-only` 세션은 mic 트랙 자체가 없으므로 이 판정을 하지 않는다. `mic (나): 0 덩어리` 면 반대로 내 발언이 안 들어간 것이다. 마이크가 다른 장치로 잡혀 있었을 수 있다. 다만 듣기만 한 회의는 이것이 정상이다.

**실시간 노트가 얼마나 덮었는지 본다.** `notes.json` 의 `coveredFromSeconds` · `coveredUntilSeconds` 를 녹음 길이와 비교해 부족하면 그대로 보고한다.

| 상황 | 무엇을 뜻하나 |
|------|------|
| `coveredFrom` 이 0 이 아니다 | 라이브가 녹음 도중에 붙었다. 그 앞은 실시간 노트에 없다 |
| `coveredUntil` 이 녹음 길이보다 짧다 | 사이클이 멈췄다. `lastError` 를 같이 본다 |
| `gaps` 가 비어 있지 않다 | 요약이 3회 실패해 포기한 구간이다. 전사본에는 남아 있다 |
| `notes.json` 이 없다 | 라이브를 안 띄웠다. 정상이다 |

라이브 노트는 미리보기이므로 부족해도 정본 요약에는 영향이 없다. 정본은 `transcript.md` 로 만든다. 사용자에게 알리는 이유는 회의 중에 본 노트가 일부만 덮었다는 사실 자체다.

전사가 끝나면 **`minutes-summary` 에이전트를 띄운다.** 인자는 세션 디렉터리 · 제목이고 산출은 `{세션}/summary.draft.md` 다. 전사본을 이 대화에서 직접 읽지 않는다 - 2시간 회의가 10만 자라 부으면 세션이 끝난다.

에이전트가 낸 초안을 읽어 **터미널에 출력하고, `config.notion.enabled` 면 같은 본문을 `config.notion.dataSource` 에 페이지로 만든다.** 묻지 않고 만든다. 회의 직후에 왕복을 늘리지 않는다.

**초안 파일이 없으면 에이전트 보고 본문에서 받아 부모가 직접 쓴다.** 하네스 정책으로 에이전트의 `Write` 가 막히는 경우가 있다. 에이전트 정의의 `tools` 에는 `Write` 가 들어 있으므로 **정의를 고치지 않는다.** 보고에 실려 온 본문을 부모가 `{세션}/summary.draft.md` 로 저장하고 그대로 진행한다.

에이전트는 Notion 을 건드리지 않는다. 페이지 생성과 id 기록은 여기서 한다. 그래야 사용자가 검토할 지점이 남는다.

**페이지를 만든 뒤 그 id 를 세션에 기록한다.**

```bash
~/.claude/bin/mtgrec notion {세션} --page-id {id} --page-url {url}
```

이것을 빠뜨리면 `/rec summary` 재실행이 그 페이지를 못 찾아 같은 회의에 페이지가 둘 남는다. `session.json` 을 손으로 편집하지 않는다. 다른 필드가 깨진다.

**`{세션}` 에는 세션 이름만 준다.** 절대경로를 주면 저장 위치를 앞에 또 붙여 `session.json 이 없습니다` 로 실패한다.

전사는 오디오 길이의 대략 1/50 시간이 걸린다. 1시간 회의면 1분 안팎이다. 처음 한 번은 ko-KR 모델(약 30초)을 내려받는다.
이어서 용어 보정이 1~2분 더 걸린다(「용어 보정」 절). 보정 결과의 변경 목록을 사용자에게 보여준 뒤 요약으로 넘어간다.

## 요약

규칙은 `references/summary.md` 가 갖고 **에이전트가 그것을 읽는다.** 문체 규격(`config.style`, 없으면 `references/style.md`)도 에이전트가 읽는다. 이 대화가 규칙 파일을 읽을 필요는 없다.

아래 다섯은 에이전트 산출을 검토할 때 보는 기준이다.

- **두 번 가공한다.** 전사본을 순서대로 훑어 바로 요약하지 않는다. 1단계에서 흩어진 발언을 주제 단위 논의 묶음으로 모으고(출력하지 않음), 2단계에서 그 묶음을 논의 순서가 아니라 중요도 순으로 재배열해 출력한다
- **세 절로 낸다.** `## 회의 결론` 2~4줄 → `## 논의 내용` 중요도 순 카드(배경 · 내용 · 결론) → `## 액션플랜`. 절 제목 셋을 바꾸지 않는다. 안건의 결론이 액션플랜으로 이어진다. 인용 · 시각이 필요하면 `transcript.md` 원문을 본다
- **터미널과 Notion 에 같은 본문을 낸다.** 제목은 `config.title.format`(기본 `[{date} {time}] {attendees} | {topic}`), 고정 속성은 `config.notion.properties`. 참석자는 캘린더 필수 참석자와 `config.attendees` 에서, 주제는 요약의 회의 결론에서 뽑는다. 서식은 Notion-flavored Markdown 이고 HTML 서식 태그를 쓰지 않는다. 속성과 페이지 분할 기준은 `references/summary.md` 의 「Notion 페이지」 절에 있다
- **실행 담당을 단정하지 않는다.** 트랙이 가르는 것은 「나 / 상대」 둘뿐이고, 상대 트랙 안에서 누가 말했는지는 모른다. `추정: ` 을 붙인다
- **없는 것을 지어내지 않는다.** 결정이 없었으면 안건 카드의 결론 자리에 `미결` 이라고 쓴다. 구조가 비어 보인다고 배경이나 결론을 채우지 않는다

정확한 인용과 시각이 필요하면 `transcript.md` 가 아니라 `transcript.json` 을 본다. 문장 단위로 쪼개진 원본과 단어 단위 시각이 거기 있다.

## 용어 보정

한국어 STT 는 도메인 용어를 거의 다 놓친다. 그래서 전사가 끝나면 보정이 붙는다.
`/rec transcribe` 와 `/rec stop` 이 자동으로 돌리고, `--no-correct` 로 끈다.

**보정은 전사만큼 더 걸리고 돈이 든다.** 실측으로 1시간 회의(572문장)에 72초, $0.36 이었다.
`/rec stop` 뒤에 사용자가 그만큼 더 기다린다는 것을 미리 말한다. 급하면 `--no-correct` 로
전사만 받고 나중에 `/rec correct` 를 돌린다.

보정은 `--effort low` 로 돈다. 찾아 바꾸기에 생각을 길게 시키면 청크마다 타임아웃이 나고
(실제로 5개 중 2개가 150초를 넘겼다) 판단이 좋아지지도 않는다.

용어집은 `~/.config/mtgrec/vocabulary.json` 하나다. 그것이 없으면 `{config.storage}/vocabulary.json` 을 읽는다 (예전 위치).
`/rec setup` 이 `references/vocabulary.example.json` 을 복사해 만든다. 필드가 셋이다.

| 필드 | 언제 듣나 | 실효 |
|------|------|------|
| `terms` | 인식 전 힌트 | 약하다. 넣어도 원인식이 잘 안 바뀐다 |
| `replacements` | 인식 후 기계적 치환 | **확실하다.** 오인식형이 항상 그 용어일 때만 넣는다 |
| `glossary` | 문맥 보정 패스가 읽는 설명 | **애매한 것을 여기서 가른다.** 정식 표기와 오인식 양상, 아닌 경우를 함께 적는다 |

### 무엇을 어느 쪽에 넣는가

이 판정을 틀리면 멀쩡한 문장이 망가진다. 아래는 LiDAR 제품 영업 회의를 가정한 판정 예다.

| 오인식형 | 실제 | 어디에 |
|------|------|------|
| `라이다` · `에스디케이` · `에프오브이` | 항상 LiDAR · SDK · FOV | `replacements` |
| `로스 투` | 항상 ROS 2 | `replacements` |
| `로스` | ROS 와 「재고 로스」가 섞임 | `glossary` |
| `클라우드` | Point Cloud 와 「클라우드 서버」가 섞임 | `glossary` |

치환은 **앞 글자가 한글이면 걸리지 않는다.** 이 규칙이 `로스` → `ROS` 를 넣었을 때
「크로스 → 크ROS」를 막는다. 뒤는 조사가 붙는 것이 정상이라 막지 않는다(`ROS로`, `ROS가`).
그래도 「로스가 생겼다」 처럼 앞이 공백인데 일반 한국어인 것은 못 막으므로, **한 글자짜리나 흔한
일반명사는 `replacements` 에 넣지 않고 `glossary` 로 보낸다.**

### 새 용어를 발견했을 때

전사본에서 틀린 용어를 보면 **사용자에게 확인받고** 용어집에 넣은 뒤 `/rec correct` 를 돌린다.
`transcribe` 를 다시 할 필요가 없다. 보정은 항상 `transcript.raw.json` 에서 다시 출발하므로
용어집을 고쳐 가며 몇 번을 돌려도 결과가 겹쳐 쌓이지 않는다.

넣기 전에 근거를 본다. 이 한 줄이면 그 오인식형이 항상 그 용어인지 아닌지 갈린다.

```
grep -ohE ".{20}로스.{20}" {저장 위치}/*/transcript.md | head -20
```

### 파일

| 파일 | |
|------|------|
| `transcript.md` · `transcript.json` | **정본.** 보정된 결과 |
| `transcript.raw.md` · `transcript.raw.json` | 보정 전 원본. 보정이 의심스러우면 여기를 본다 |

문맥 보정의 규칙은 `references/correct.md` 에 있다. 판정이 자꾸 틀리면 그 파일의 판정 기준
표에 사례를 더한다. 재빌드가 필요 없다.

## `/rec clean`

```
~/.claude/bin/mtgrec clean --days 14 --dry-run
```

**항상 `--dry-run` 을 먼저 돌려 지울 목록을 보여주고 확인을 받는다.** 오디오는 복구되지 않는다.
전사본이 없는 세션의 오디오는 도구가 알아서 건너뛴다.

## 어디까지가 이 스킬인가

녹음 · 전사 · 용어 보정 · 요약 · 요약 Notion 페이지까지다. 그 뒤의 문서화는 이 스킬이 묻지 않는다.

`/rec stop` 의 마지막 한 줄은 `config.handoff` 의 문장이다. 없으면 「페이지에서 액션플랜의 담당과 기한을 손보십시오.」 다. 팀에 회의록을 정본으로 올리는 별도 절차(다른 스킬)가 있으면 그 안내를 `handoff` 에 적는다.

## 지켜야 할 것

- **오디오를 외부로 보내지 않는다.** 전사는 전부 온디바이스다. 클라우드 STT 로 우회하지 않는다
- **`transcript.md` 를 요약으로 대체하지 않는다.** 전문이 원본이고 요약은 파생물이다
- **Notion 페이지에 전사 전문을 붙이지 않는다.** 페이지는 요약이고 전문은 단말에 있는 `transcript.md` 다. 인용이 필요하면 세션 경로만 적는다
- **용어 보정이 지어낸 것을 그대로 믿지 않는다.** 보정은 오인식을 고치는 것이지 뜻을 정하는 것이 아니다.
  보정 결과에서 처음 보는 시스템 이름이나 약어가 나오면 용어집을 의심한다. 실제로 있지도 않은
  약어를 용어집에 넣었더니 철자가 비슷한 멀쩡한 약어가 전부 그것으로 바뀐 적이 있다
- **실시간 전사와 노트는 미리보기다.** 스트리밍 인식이라 종료 후 파일 단위 패스보다 품질이 낮다.
  요약과 인용은 `live.jsonl` · `notes.json` 이 아니라 `transcript.md` · `transcript.json` 으로 한다.
  `/rec stop` 은 페이지에 노트가 이미 있어도 정본 요약을 다시 만든다
- 전사본에 없는 발언을 요약에 넣지 않는다. 맥락상 그랬을 것 같아도 쓰지 않는다
- **요약 구조를 채우려고 내용을 만들지 않는다.** 배경이 전사본에 없으면 그 항목을 빼고, 결론이 없으면 `미결` 로 둔다
- 화자가 「상대」인 발언에 특정인 이름을 붙이지 않는다. 사용자가 지목해 준 것만 쓴다
