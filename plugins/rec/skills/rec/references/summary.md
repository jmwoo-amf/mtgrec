# 요약 형식

**`minutes-summary` 에이전트가 읽는 파일이다.** 부모 대화는 이것을 읽지 않고 에이전트가 낸 초안을 검토한다. 단, 「Notion 페이지」 절부터는 부모 대화가 한다.

사용자별 값은 `~/.config/mtgrec/config.json` 에 있다 (`MTGREC_CONFIG_DIR` 가 있으면 그 아래). 필드 정의는 `references/setup.md` 의 「config.json」 절에 있다. 이 파일에서 `config.X` 라고 쓴 것은 그 파일의 필드다.

문체 규격은 `config.style` 의 파일들이 정한다. 비어 있으면 이 스킬의 `references/style.md` 다. 이 파일이 정하는 것은 구조(절 · 카드 · 상한)이고 종결과 어휘는 문체 파일이 정본이다. 어긋나면 문체 파일을 따른다.

에이전트는 `transcript.md` 를 읽고 요약을 만들어 `summary.draft.md` 에 쓴다. 그 뒤 부모 대화가 **터미널에 출력하고, `config.notion.enabled` 가 참이면 같은 내용을 Notion 페이지로 만든다.** 로컬에는 `summary.draft.md` 하나만 남는다.

이 요약은 회의의 논지를 빠르게 되짚는 용도다. 그래서 인용 · 시각 · 참석자 표 같은 기록용 장치를 넣지 않는다. 정확한 인용이 필요하면 `transcript.md` 원문을 본다.

## 두 번 가공한다

한 번에 요약으로 건너뛰지 않는다. 전사본은 발언 순서대로 흐르고 같은 주제가 여러 번 끊겨 돌아오므로, 순서대로 훑어 만든 요약은 회의의 논지가 아니라 발언의 잔해가 된다.

**1단계 (추출, 출력하지 않음).** 전사본을 처음부터 끝까지 읽고 논의 묶음을 만든다.

- 흩어진 발언을 **주제 단위로 모은다.** 00:07 과 00:53 에 나온 같은 주제는 한 묶음이다
- 묶음마다 배경 · 내용 · 결론의 재료를 뽑는다. 재료가 없는 칸은 비워 둔다
- 요청 표현("~부탁드립니다", "~확인해 주세요", "~까지 주시면", "~정리해서 공유")을 전부 훑어 액션 후보를 따로 모은다
- 잡담, 화면 조작, 인사, 되풀이는 버린다

**2단계 (재구조화, 이것을 출력한다).** 묶음을 논의 순서가 아니라 **중요도 순으로** 재배열하고 아래 형식으로 쓴다.

중요도 판정 기준은 순서대로 이렇다.

1. 뒤따르는 작업의 방향을 바꾸는 것 (결정, 반려, 전제의 변경)
2. 막고 있는 것 (미결이라서 다른 일이 못 나가는 것)
3. 알아야 하는 사실 (확인된 데이터, 대외 일정, 제약)

## 출력 형식

세 절이다. **터미널과 Notion 페이지가 같은 서식을 쓴다.** 절 제목 셋(`## 회의 결론` · `## 논의 내용` · `## 액션플랜`)을 바꾸지 않는다.

```markdown
## 회의 결론

1. {이 회의가 무엇을 정했거나 무엇에 막혔는지를 3줄 안팎으로. 안건 카드를 읽지 않아도 회의의 성격이 잡히게 쓴다}
2. 실외 구간의 FOV 요구가 확정되지 않아 모델을 정하지 못함
3. 견적은 SDK 라이선스를 분리해 다시 낸다

## 논의 내용

### 1. PoC 에 어떤 모델을 몇 대 투입할 것인가

- **배경:** 고객이 물류센터 지게차 충돌 방지 용도로 실내 테스트를 요청함
- **내용:** 2대로 시작하자는 쪽과 커버리지 때문에 3대가 필요하다는 쪽이 갈림
- **결론:** 2대로 시작하고 결과를 보고 추가. 잠정

### 2. 실외 출입구까지 한 대의 FOV 로 덮을 수 있는가

- **배경:** 출입구 쪽 실외 구간도 감지해 달라는 요청이 나옴
- **내용:** 현 모델의 수평 FOV 로는 사각이 생긴다는 의견이 있었음
- **결론:** 미결. 고객의 감지 범위 도면이 있어야 판단 가능

## 액션플랜

- 감지 범위 도면 공유 요청 (추정: 상대)
- SDK 라이선스 분리 견적 재발행 (추정: 나)
```

`배경` · `내용` · `결론` 은 불렛으로 쓴다. 두 칸 띄어쓰기로 줄을 나누면 Notion 에서 한 블록으로 붙는다.

### 절별 규칙

| 절 | 규칙 |
|------|------|
| 회의 결론 | 2~4줄. 안건 카드의 결론을 그대로 옮겨 붙이지 않고 회의 전체를 관통하는 것만 쓴다. 막힌 회의면 무엇에 막혔는지를 쓴다 |
| 논의 내용 | 중요도 순 번호. 3~7개. 제목은 명사구가 아니라 **그 자리에서 다룬 질문**으로 쓴다 (`PoC 장비 구성` 이 아니라 `PoC 에 어떤 모델을 몇 대 투입할 것인가`) |
| 배경 | 이 논의가 왜 열렸는지. 한 줄. 전사본에 배경이 없으면 칸을 비우지 말고 항목 자체를 뺀다 |
| 내용 | 오간 쟁점. 한두 줄. 양쪽 입장이 갈렸으면 갈렸다고 쓴다 |
| 결론 | 정해진 것. 안 정해졌으면 `미결` 로 쓰고 무엇이 걸려 있는지 적는다. 잠정이면 잠정이라고 쓴다 |
| 액션플랜 | 표가 아니라 불렛. 담당과 기한은 괄호로 항목 끝에. 안건 순서가 아니라 급한 순서 |

액션플랜은 요청 표현을 전부 훑어 뽑는다. **가장 자주 새는 지점이다.** 없으면 `액션 아이템 없음.` 한 줄로 끝낸다.

## 원칙

- **추출이지 창작이 아니다.** 전사본에 있는 말만 쓴다. 맥락으로 짐작한 것을 넣지 않는다. 구조가 비어 보인다고 배경이나 결론을 지어내지 않는다
- **실행 담당을 단정하지 않는다.** 트랙이 가르는 것은 「나 / 상대」 둘뿐이다. 추론한 담당에는 `추정: ` 을 붙인다. 두 트랙 중 하나가 비어 화자 구분이 없었으면 요약 앞에 그 사실을 먼저 알린다
- **없는 것을 지어내지 않는다.** 결정이 없었으면 안건 카드의 결론 자리에 `미결` 이라고 쓴다. 회의 전체에 결정이 없었으면 「회의 결론」에 그렇게 쓴다
- 숫자 · 식별자 · 날짜가 문맥과 어긋나면 고치지 말고 `(전사 불확실)` 을 붙인다

## Notion 페이지

여기부터는 **부모 대화가 한다.** 에이전트는 Notion 을 건드리지 않는다.

`config.notion.enabled` 가 거짓이거나 `config.notion` 이 없으면 이 절을 건너뛴다. 터미널 출력과 `{세션}/summary.draft.md` 로 끝난다.

터미널 출력과 **같은 본문**을 `config.notion.dataSource` 에 페이지로 만든다. 요약을 두 번 쓰지 않는다.

| 항목 | 값 |
|------|------|
| 부모 | `config.notion.dataSource` (`collection://...`) |
| 제목 | `config.title.format` 을 채운 것. 아래 「제목」 절이 칸을 정한다 |
| 아이콘 | `config.notion.icon`. 비어 있으면 붙이지 않는다. 생성할 때 `icon` 파라미터로 붙인다 |
| 고정 속성 | `config.notion.properties` 의 키 · 값을 그대로 넣는다. 사람 속성(person)은 이름으로 사용자를 찾아 넣는다 |
| 판정 속성 | `config.notion.inferred` 의 키마다 값에 적힌 지시대로 내용을 보고 정한다. 가리기 어려우면 비워 둔다 |

### 제목

**처음부터 최종 제목을 만든다.** `녹음 요약` 같은 표시를 넣지 않는다.

`config.title.format` 의 자리표시자는 넷이다.

| 자리표시자 | 값 |
|------|------|
| `{date}` | 녹음 시작 날짜 `YY.MM.DD` |
| `{time}` | 녹음 시작 시각 `HH:MM` |
| `{attendees}` | 아래 「참석자 칸」 |
| `{topic}` | 아래 「주제 칸」 |

형식이 없으면 `[{date} {time}] {attendees} | {topic}` 을 쓴다.

#### 참석자 칸

`config.attendees` 가 정한다. **캘린더 초대의 필수 참석자만 세고 `optionalAttendee` 는 세지 않는다.** 본인(`config.email`)은 내부 참석자로 센다. 캘린더 커넥터가 없거나 걸리는 일정이 없으면 `config.attendees.fallback` 을 쓰고 그 사실을 응답에 한 줄 적는다.

| 필수 참석 | 참석자 칸 |
|------|------|
| `internalDomains` 밖의 주소가 하나라도 있다 | 그 조직명을 ` · ` 로 잇는다. `orgAliases` 에 있으면 약칭을 쓴다 |
| 전원 `internalDomains` 안 | `people` 로 각 주소의 역할을 찾고, 역할 집합이 `groups[].roles` 와 같은 항목의 `label` 을 쓴다 |
| `groups` 가 비어 있다 | `fallback` 을 쓴다 |

**매핑에 없는 주소가 오면 지어내지 않는다.** 사외 조직을 못 가리거나 내부 그룹이 안 갈리면 그때만 `AskUserQuestion` 을 한 번 낸다.

#### 주제 칸

**요약이 나온 뒤 회의 결론에서 뽑는다.** 캘린더 일정 제목을 그대로 쓰지 않는다. 매일 도는 슬롯은 제목이 매번 같아 목록에서 구분이 안 된다.

| 상황 | 주제 |
|------|------|
| 매일 · 매주 도는 슬롯 | 슬롯 이름 뒤에 그날 핵심: `주간 영업 회의 - 물류센터 PoC 일정 확정` |
| 회차가 있는 회의 | `정기회의 10차` (회차는 참석자 칸이 아니라 주제로 간다) |
| 그 밖 | 다룬 것 한 줄: `고객사 실외 설치 조건 청취` |

**참석자 칸과 겹치는 낱말을 주제에 다시 쓰지 않는다.** `영업팀 | 영업팀 주간 회의` 처럼 같은 말이 두 번 나오면 안 된다.

### 본문 머리

본문 맨 위에 한 줄로 출처를 박는다. 그 밖에 문서가 자기를 설명하는 문장을 넣지 않는다.

```
`로컬 녹음 전사 기준` · 2026-09-01 14:03 ~ 16:31 (02:28:07) · `{세션 경로}`
```

### 서식

- **Notion-flavored Markdown 이다.** 강조는 `**볼드**`, HTML 서식 태그(`<strong>` · `<em>`)를 쓰지 않는다. 문자 그대로 출력되어 양식이 깨진다
- 절 제목은 `##`, 안건 카드는 `###`. h4 이하로 내려가지 않는다
- 표를 쓰지 않는다. 요약은 불렛과 카드로 끝낸다
- 세션 경로 · 시각 · 파일명은 인라인 코드로 감싼다
- **한글을 그대로 넣는다.** `\uXXXX` 이스케이프로 본문을 보내면 음절이 깨진다 (`테이블` → `테이붔`, `액션플랜` → `액션픹`). 서식 태그는 멀쩡해 보이므로 눈에 잘 안 띈다
- **만든 뒤 `notion-fetch` 로 한 번 읽어 확인한다.** 깨졌으면 `replace_content` 로 다시 쓴다

### 페이지를 나누는 기준

| 상황 | 처리 |
|------|------|
| 캘린더 일정 두 개가 한 녹음에 들어옴 | **페이지를 둘로 나눈다.** 각각 자기 시작 시각을 제목에 쓴다 |
| 다른 대화가 짧게 겹쳐 흐름 (전화 · 옆자리) | 한 페이지 안에 `## 겹쳐 녹음된 별건` 절로 둔다 |
| 녹음 전체가 세션 제목과 다른 주제 | 페이지 제목을 실제 주제로 쓴다. 세션 이름을 믿지 않는다 |

### 만든 뒤

페이지 id 를 세션에 기록한다. 이것을 빠뜨리면 `/rec summary` 재실행이 그 페이지를 못 찾아 같은 회의에 페이지가 둘 남는다.

```bash
~/.claude/bin/mtgrec notion {세션 이름} --page-id {id} --page-url {url}
```

`session.json` 을 손으로 편집하지 않는다. 다른 필드가 깨진다.

응답에는 **페이지 URL 과 제목만** 적는다. 요약 본문을 응답에서 다시 설명하지 않는다.

### 다시 만들 때

`/rec summary` 는 `session.json` 의 `notionPageId` 를 먼저 본다.

| 상태 | 처리 |
|------|------|
| 값이 있다 | 그 페이지를 `notion-fetch` 로 읽어 제목을 보여주고 **갱신할지 묻는다.** 승낙하면 `replace_content` 로 본문을 통째로 바꾼다. 새 페이지를 만들지 않는다 |
| 값이 있는데 페이지가 없다 (지웠다) | 새로 만들고 id 를 다시 기록한다 |
| 값이 없다 | 터미널에만 낸다. Notion 에도 올릴지는 사용자가 말할 때 한다 |

**본문을 부분 수정하지 않는다.** 요약은 1단계 묶음에서 다시 나오는 것이라 절 하나만 갈아 끼우면 나머지와 어긋난다. 통째로 바꾼다.

사용자가 손으로 고친 페이지를 덮을 수 있다. 갱신 전에 `notion-fetch` 로 읽은 본문이 이전 요약과 다르면 그 사실을 알리고 다시 묻는다.

## 마지막에 할 것

`config.handoff` 가 있으면 그 문장을 한 줄로 그대로 안내한다. 없으면 **「페이지에서 액션플랜의 담당과 기한을 손보십시오.」** 한 줄이다. 담당과 기한은 전사본으로 못 정하는 것이므로 사람이 그 자리에서 채운다.
