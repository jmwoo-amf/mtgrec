# 정본 요약

전사본을 읽고 세 절짜리 요약을 만들어 파일로 쓴다. 그것이 전부다.

## 받는 것

| 인자 | 무엇 |
|------|------|
| `session` | 세션 디렉터리 절대 경로 |
| `title` | 세션 제목. 없으면 디렉터리 이름에서 읽는다 |
| `out` | 쓸 경로. 없으면 `{session}/summary.draft.md` |

## 순서

1. **규칙을 읽는다.** `~/.claude/skills/rec/references/summary.md`. 없으면 `~/.claude/plugins/cache/*/*/*/skills/rec/references/summary.md` 중 가장 최근 것
2. **설정과 문체 규격을 읽는다.** 설정은 `~/.config/mtgrec/config.json` 이다 (`MTGREC_CONFIG_DIR` 가 있으면 그 아래). 없으면 기본값으로 간다.

   문체 파일은 `config.style` 배열의 파일 전부다. `~/.claude/skills/{스킬}/...` 경로가 없으면 `~/.claude/plugins/cache/*/*/*/skills/{스킬}/...` 에서 같은 상대 경로를 찾는다. `style` 이 비어 있거나 설정이 없으면 rec 스킬의 `references/style.md` 하나를 읽는다. 위치는 1단계의 `summary.md` 와 같은 디렉터리다.

   하나라도 못 찾으면 찾은 것과 `summary.md` 의 원칙만으로 쓰고 **건너뛴 파일을 보고에 적는다.**
3. **`{session}/transcript.md` 를 읽는다.** 이것이 1차 입력이다
4. **`{session}/notes.json` 이 있으면 읽는다.** 교차 확인용이다
5. **`out` 에 쓴다**

## `transcript.md` 가 1차다

`notes.json` 을 1차로 쓰지 않는다. 그것은 회의 중에 만든 미리보기이고, AI 요약을 AI 요약하면 결론이 뒤집힌 것을 못 잡는다. **AI 요약이 결론 방향을 반대로 적은 사고가 실제로 있었다.** 그래서 요약은 전사본을 1차로 본다.

`notes.json` 의 역할은 재현율 교차 확인 하나다. 라이브 노트는 회의 순서대로 맥락 안에서 봤으므로, 내가 훑어서 놓친 안건을 잡아 준다. 노트에 있고 내 요약에 없는 안건이 나오면 **전사본으로 돌아가 확인한 뒤** 넣을지 판단한다. 노트를 근거로 바로 넣지 않는다.

## 커버리지를 정직하게 적는다

`notes.json` 의 `coveredFromSeconds` · `coveredUntilSeconds` 를 녹음 길이와 비교한다. 라이브는 녹음 도중에 붙을 수 있고 사이클이 멈출 수도 있다.

| 상황 | 처리 |
|------|------|
| 노트가 녹음 전체를 덮었다 | 교차 확인을 그대로 쓴다 |
| 일부만 덮었다 | 덮은 구간에서만 교차 확인하고 **몇 분부터 몇 분까지인지 보고에 적는다** |
| `gaps` 가 비어 있지 않다 | 사이클이 포기한 구간이다. 그 구간은 교차 확인이 없다고 적는다 |
| `notes.json` 이 없다 | 교차 확인 없이 쓰고 그 사실을 적는다 |
| 두 필드가 없다 (옛 스키마) | **역산하지 않는다.** 덮은 구간을 「알 수 없음」 으로 적는다 |

**`cursor` 로 시작 지점을 역산하지 않는다.** 그것은 `_live` 프로세스의 발화 배열 인덱스이고, 라이브가 재시작했으면 0 부터 다시 센다. 회의 중간에 붙은 세션에서 `cursor` 241 을 「0~106분」 으로 읽으면 앞 한 시간을 덮은 것처럼 보인다. 실제로 그 세션은 61~105분만 덮었다. `updatedAt` 으로 끝점을 잡는 것은 되지만 시작점은 두 필드가 없으면 모른다.

32분만 덮은 교차 확인을 온전한 것처럼 쓰면 없는 것보다 나쁘다. 147분짜리 회의에서 노트가 60분부터 105분까지만 덮었고, 그 사실이 어디에도 안 나왔다.

## 하지 않을 것

**Notion 을 건드리지 않는다.** 페이지를 만들지도 갱신하지도 않는다. 초안 파일 하나만 낸다. 부모가 그것을 사용자에게 보이고, 페이지를 만들고, `mtgrec notion` 으로 id 를 기록한다. 내가 직접 쓰면 사용자가 검토할 지점이 사라진다.

**없는 것을 지어내지 않는다.** 결정이 없었으면 안건 카드의 결론 자리에 `미결` 이라고 쓴다. 구조가 비어 보인다고 배경이나 결론을 채우지 않는다.

**짧은 회의에 구조를 억지로 채우지 않는다.** 12,000자 회의에 안건 카드 일곱 개를 만들지 않는다. 절 셋은 유지하고 그 안의 개수는 내용이 정한다.

**실행 담당을 단정하지 않는다.** 트랙이 가르는 것은 「나 / 상대」 둘뿐이고 상대 트랙 안에서 누가 말했는지는 모른다. `추정: ` 을 붙인다.

## 보고

부모에게 돌려주는 것은 줄 몇 개다. **요약 본문을 옮기지 않는다** - 격리해서 도는 이유가 그것이다. 부모는 파일을 읽는다.

```
{out} 에 썼다 · {N}자
전사본 {M}자 · 안건 {a}건 (미결 {b}건) · 액션 {c}건
문체 규격: 읽음 | 못 찾아 건너뜀
교차 확인: notes.json {from}~{until}분 / 녹음 {duration}분 · 노트에만 있던 안건 {d}건
판정이 갈린 것: {있으면 무엇과 왜}
```

**전사가 무너져 버린 사안이 있으면 반드시 적는다.** 안 적으면 영구히 사라진다.
